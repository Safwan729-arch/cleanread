## 2026-09-12

Bug report from real use: equations on the Wikipedia Navier–Stokes article were unreadable
in the reader. Reproduced against the live page, found **two** independent causes, fixed
both — see [[math-rendering]].

1. **Inline maths was forced onto its own centred line.** Not a maths bug: `reader.css`
   forced every `img` to `display:block`, on the assumption that images are photographs.
   Images are now inline by default and only become figures when they stand alone. Block
   images on that article went 245 → 69, and inline icons on every other site benefit too.
2. **Black maths on a dark background.** The SVGs are black glyphs on transparency;
   the dark theme now inverts them, and print resets the inversion.

Also in this pass:
- `tagMath()` runs between the scrub and `stripClasses()`, because the site's class is the
  only thing identifying an SVG as an equation
- dropped `aria-hidden` from maths images so screen readers can reach the LaTeX alt text
- Wikipedia `[edit]` section links are scrubbed (`editsection` token)
- Markdown export emits real LaTeX (`$…$`, `$$…$$`) instead of an image of an equation
- matching maths rules added to the PDF stylesheet, which had the same block-image trap

New deterministic fixture `scripts/fixtures/math-article.html` mirrors MediaWiki's markup,
so this is covered without depending on the network. Smoke test now 107 checks.

Closed the loose ends from yesterday as well: print-to-PDF (real selectable text),
`build.target` pinned so `minimum_chrome_version` is enforced rather than assumed,
`PRIVACY.md`, listing copy and the 440x280 promo tile — see [[store-packaging]].

Second bug report, same day: graphs and images stripped on an openai.com article. That URL
is behind a Cloudflare challenge so it could not be loaded headless — reproduced the
*mechanisms* against a new fixture instead. Four separate causes, all fixed — see
[[media-preservation]]. The worst was our own scrub: `<figure class="article-banner">`
matched the `banner` junk token, so the extension deleted the article hero itself.
Smoke test now 115 checks.

TODO next: nothing outstanding. Publishing the privacy policy URL is the only step that
needs a person.

Third report, same day: "the extension is not working, it says it can't work for this
website." The message was ours. Root cause was not the media change at all — it was the
*act of updating*: reloading the extension tears the content script out of tabs that are
already open, and Chrome never re-injects it. Reproduced it directly (`sendMessage` →
"Receiving end does not exist" after a reload, fine again after a tab reload), then fixed
it in two layers — see [[content-script-lifecycle]].

First attempt failed, usefully: injecting from the popup threw *"Cannot access contents of
the page"*, because `activeTab` is only granted by a real toolbar click. That forced
`host_permissions` for `http`/`https` — the same set `content_scripts` already matches, so
no new install warning. Smoke test now 121 checks, including one that reloads the
extension mid-run and asserts an open tab still cleans without a page reload.

Fourth report: charts missing on the openai.com article, and its chart toggles not
replicated. This time the page **could** be loaded — the Cloudflare challenge passes in a
real headful Chrome, though not headless — so this was diagnosed and verified against the
live site rather than a fixture.

Measured: 12 charts on the page, **0 in the reader**, while their captions came through
perfectly. Three independent causes in Readability, none of them ours — see
[[chart-preservation]]. The one worth remembering: `_getClassWeight` docks 25 points for
the bare substring `scroll` in a class name, and the wrapper's class was
`scroll-mt-anchor-offset`, a Tailwind scroll-margin utility. Modern utility classes collide
with a blocklist written for 2010 markup.

After the fix: 12 of 12, verified twice on the live page. A first version passed every
count and still looked broken — white axis labels frozen onto a pale background — caught
only by looking at the screenshot. Charts now carry their own panel when their ink is
light.

Toggles are recorded, not replicated: a static reader cannot re-run Vega, so the reader
names the other views instead of implying one series is the whole picture.

New fixture `scripts/fixtures/chart-article.html`; smoke test now 133 checks.
